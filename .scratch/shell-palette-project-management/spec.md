# Spec: 三栏外壳底色与项目管理界面

## Problem Statement

桌面端与 Web 的外壳三栏（主导航栏、中间导航、主内容）仍使用旧的暖灰底色，与 rukie.pen 更新后的中性底色不一致；中间导航与主内容组成的内侧工作区也没有边缘深度，和主导航栏之间的层次只能靠分隔线区分。

Project 创建后无法再管理：不能改名、不能增删目录、不能从应用中移除，只能在欢迎页的“项目目录”弹窗里切换主目录。创建弹窗没有名称输入，目录行直接显示完整路径，长路径挤占空间；在 Web 环境里还会退回手动填写路径。侧栏的项目行既没有悬停反馈，也无法快速查看一个 Project 包含哪些目录、有多少会话。

## Solution

- 外壳三栏改用 DESIGN.md 中的新底色：主导航栏与标题栏共用一个值，中间导航与主内容各一个值；中间导航加主内容作为一个整体，外围投下两层柔和阴影，设置页同样适用。几何与分隔线保持不变。
- 创建项目弹窗（C27）提供必填名称和源文件夹列表；点击“创建项目”时，统一弹出信任确认（C28），列出全部目录并标出主目录。
- 目录行只显示目录名；悬停或聚焦时，在行上方显示完整路径提示，非主要目录同时显示“设为主要”。
- 新增编辑项目弹窗（C29）：改名、增删目录、设为主要、移除本地项目。移除前先弹确认框（C31），只删除登记，文件与会话都保留。
- 悬停或聚焦侧栏项目行时显示项目详情卡（C30）：名称、会话数、全部目录和“编辑项目”入口，可用图钉临时固定。
- 项目行按 C02 增加悬停与选中背景，悬停时显示“新建会话”。项目“⋯”菜单与右键菜单本次不做。

设计源为仓库外的 `/Users/chenzheng/Desktop/rukie.pen`：C01 外壳与 M01-B 三栏对照、C02 会话侧栏、M02-B 中的 C27–C31，以及 H01-H、H02、H02-T、H04 页面流程。

## User Stories

1. 作为桌面端用户，我希望主导航栏和标题栏使用同一个中性底色，这样外壳顶部和左侧连成一体。
2. 作为用户，我希望中间导航与主内容分别使用比主导航栏更浅（Light）或更深（Dark）的底色，这样三栏层次清楚。
3. 作为用户，我希望中间导航与主内容作为一个整体浮在主导航栏之上，四周有柔和阴影，这样工作区和外壳的边界不依赖描边。
4. 作为用户，我希望中间导航与主内容之间只有一条 1px 分隔线，没有第二层阴影，这样两栏仍读作一个工作区。
5. 作为用户，我希望设置页也呈现同样的三栏底色和工作区阴影，这样切换到设置时外壳不跳变。
6. 作为用户，我希望 Dark 主题下阴影只加深边缘，不出现发光或渐变底色，这样暗色界面保持克制。
7. 作为用户，我希望调整底色后栏宽、标题栏高度、圆角、4px 外侧留白和滚动位置都不变，这样已有布局不受影响。
8. 作为用户，我希望 System 主题跟随系统切换时三栏底色同步变化，这样主题选择行为一致。
9. 作为用户，我希望创建项目时先填写项目名称，这样 Project 在侧栏中显示我想要的名字。
10. 作为用户，我希望添加第一个文件夹时，如果名称为空，自动填入该目录名，并且仍可修改，这样常见情况不用手动输入。
11. 作为用户，我希望名称为空或没有任何文件夹时“创建项目”不可用，这样不会提交不完整的项目。
12. 作为用户，我希望还没有文件夹时看到一个空状态入口，点击即可选择文件夹，这样第一步很明确。
13. 作为用户，我希望已添加的文件夹按顺序排成列表，末尾有“添加文件夹”行，这样可以继续追加目录。
14. 作为用户，我希望第一个文件夹默认是主目录并显示“主要”标记，这样单目录项目无需额外操作。
15. 作为用户，我希望在创建弹窗里也能移除误加的文件夹，这样提交前可以修正选择。
16. 作为用户，我希望点击“创建项目”时弹出一个信任确认，列出全部目录的完整路径并标出主目录，这样一次确认整个项目。
17. 作为用户，我希望信任确认说明 Rukie 可以读取、编辑和运行这些文件夹中的文件，且文件夹设置可能触发代码自动运行，这样我清楚信任的后果。
18. 作为用户，我希望取消、关闭或按 Esc 退出信任确认后回到创建表单，已填写的名称和目录都保留，这样不必重新填写。
19. 作为用户，我希望确认信任后项目立即创建并出现在侧栏，这样可以直接开始会话。
20. 作为 Web 环境用户，我希望在无法打开系统文件夹选择器时看到明确提示，并且可以重试，这样我知道原因而不是看到无反应。
21. 作为用户，我希望目录行只显示目录名，这样列表紧凑易读。
22. 作为用户，我希望两个目录同名时，名称后附带父目录名，这样能区分它们。
23. 作为用户，我希望悬停或聚焦目录行时，在行上方看到完整路径提示，这样能确认目录的确切位置。
24. 作为用户，我希望悬停或聚焦非主要目录时出现“设为主要”，点击后它成为主目录，这样可以改变新会话的工作目录。
25. 作为用户，我希望“设为主要”出现时行内其他元素不移动，这样悬停不会造成跳动。
26. 作为用户，我希望从项目详情卡进入编辑项目弹窗，看到当前名称和全部源文件夹，这样能在一个地方管理项目。
27. 作为用户，我希望在编辑弹窗中修改项目名称并保存，这样名称可以随工作调整。
28. 作为用户，我希望在编辑弹窗中添加文件夹；如果项目已受信任，保存时统一确认信任，新增的目录带“新增”标记，这样新目录不会绕过信任确认。
29. 作为用户，我希望未受信任的项目新增目录时不在保存时提示，下次打开会话时再按原有流程确认，这样信任仍只在需要时询问。
30. 作为用户，我希望在编辑弹窗中移除文件夹；移除主目录时下一个目录自动成为主目录，最后一个目录不能移除，这样项目始终有效。
31. 作为用户，我希望移除某个目录后，工作目录正好是它的会话回到“对话”分组，会话与文件都不受影响，这样移除只改变组织方式。
32. 作为用户，我希望编辑时与其他项目目录重叠会被拒绝，并显示冲突的项目名，这样一个目录只属于一个项目。
33. 作为用户，我希望取消、关闭或按 Esc 退出编辑弹窗时放弃所有修改，这样误操作不会生效。
34. 作为用户，我希望没有修改或名称为空时“保存”不可用，这样不会提交无效内容。
35. 作为用户，我希望点击“移除本地项目”后看到确认框，标题带项目名，说明文件和现有聊天不会被删除，这样我确认后果再操作。
36. 作为用户，我希望确认移除后项目从侧栏消失，它的会话回到“对话”，置顶与归档状态保留，这样不会丢失任何会话。
37. 作为用户，我希望取消移除时回到编辑弹窗，这样可以继续编辑。
38. 作为用户，我希望项目下有会话正在运行或等待交互时不能移除项目，这样不会打断进行中的工作。
39. 作为用户，我希望悬停或聚焦侧栏项目行时显示项目详情卡，这样无需展开就能看到项目概况。
40. 作为用户，我希望详情卡显示名称、未归档的会话数和全部目录的完整路径（家目录缩写为 `~`），这样能快速核对项目内容。
41. 作为用户，我希望详情卡出现在项目行悬停背景右侧 4px、顶边对齐，可以覆盖中间导航，这样卡片贴近来源而不遮挡项目行。
42. 作为用户，我希望指针从项目行移向详情卡时卡片不消失，这样可以点击卡片里的操作。
43. 作为用户，我希望点击图钉后卡片在指针离开时保持打开，再次点击图钉、按 Esc 或点击外部才关闭，这样可以边看边操作。
44. 作为用户，我希望点击详情卡中的“编辑项目”打开编辑弹窗，这样管理入口就在详情旁边。
45. 作为用户，我希望项目行有悬停背景，当前会话所属的项目行有选中背景，这样能看出位置和可点击性。
46. 作为用户，我希望悬停或聚焦项目行时显示“新建会话”，这样能快速在该项目中开始工作。
47. 作为键盘用户，我希望目录行、“设为主要”、移除按钮、详情卡、图钉和所有弹窗都可以用键盘到达，有可见焦点和无障碍名称，这样不用鼠标也能完成全部操作。
48. 作为用户，我希望所有新文案在中文和英文界面都正确显示，这样切换语言后界面完整。
49. 作为用户，我希望 Light 与 Dark 主题下所有新界面都符合 DESIGN.md 与 rukie.pen，这样视觉一致。
50. 作为窄窗口用户，我希望弹窗内距收窄为 16px，路径可换行，详情卡不超出视口，这样小窗口中也能完整操作。

## Implementation Decisions

### 外壳三栏底色与工作区阴影

- 四个 C01 结构 token 取 DESIGN.md [Workspace structure](../../DESIGN.md#workspace-structure) 的值：`layout-rail` 与 `layout-titlebar` 为 Light `#F7F7F7` / Dark `#0E0E0E`，`layout-sidebar` 为 `#FCFCFC` / `#050505`，`layout-content` 为 `#FFFFFF` / `#000000`。`layout-divider` 不变。
- 新增 `layout-shadow-near`（Light `#0000000A` / Dark `#00000040`）与 `layout-shadow-far`（`#0000000F` / `#00000073`），在内侧工作区容器上合成两层外阴影：`0 2px 8px` 与 `0 8px 24px`。阴影只出现一次，跟随 12px 工作区圆角，不加在中间导航、主内容、卡片或控件上。
- 阴影位于外层窗口裁剪内，不改变 52px 主导航栏、268px 中间导航、44px 标题栏、4px 右/下留白和滚动归属。两栏底色保持不透明；它们之间的接缝仍只有 1px 分隔线。
- 设置页复用同一外层壳与内侧工作区几何，同样显示阴影；设置内部表面的作用域 token 保持不变。
- 这是 DESIGN.md 中 C01 的作用域结构深度例外，不扩展到其他工作区表面。

### Project 数据与 wire 命令

- `WireProject` 已有 `name`。`project.create` 新增必填 `name`：去除首尾空白后长度为 1–128。选中的主目录已经是某个 Project 的主目录时，仍返回该 Project，不修改其名称。
- 新增 `project.update { projectId, name, directories, primary, trusted? }`，提交编辑后的完整状态。服务端复用创建时的校验：绝对路径、目录存在、真实路径去重、应用数据根保留（`project_reserved`）、与其他 Project 重叠（`project_conflict` 加冲突项目名，排除自身）。此外要求 `directories` 非空且 `primary` 属于它；名称规则与创建相同。
- 信任提升：已信任的 Project 新增目录时，请求必须携带 `trusted: true`，否则以 `project_trust_required` 拒绝，这样服务端保证新目录不会绕过确认。未信任的 Project 新增目录后保持未信任，之后打开会话时沿用已有的补确认流程。只改名、只移除目录或只切换主目录时不需要 `trusted`。
- 新增 `project.remove { projectId }`：删除 registry 登记，不触碰任何目录文件、Session Transcript、置顶或归档状态。该 Project 任一目录下有 Session 执行中或等待交互时，以 `session_busy` 拒绝。
- 所有 Project 变更都进入现有的 Project 变更队列，成功后发出现有的变更事件。
- 编辑后重新派生打开状态：现有 Session 的 cwd 不变。打开会话时，仍按“cwd 等于某个 Project 任一目录”判断归属，并由此派生附加目录与 `trustedProjects`。已打开且空闲的 Session 在下一次空闲执行时关闭并以新配置重开，沿用信任更新的重开机制；活跃 Run 不被中断。cwd 不再属于任何 Project 的会话按“对话”打开，不再获得项目级信任。
- 会话数在 UI 中由 Session 摘要派生：统计 `projectId` 指向该 Project、且未归档的 Session，包含已置顶的。server 用真实目录身份提供必填 `projectId: string | null`，UI 的分组、标题、搜索、计数、选中、信任提示与移动目标共享它；旧 Session cwd 保留原样。wire 不新增计数字段。

### 创建项目（C27）与统一信任确认（C28）

- 创建弹窗宽 480px。名称输入框自动获得焦点，左侧带文件夹图标。没有目录时显示 104px 的空状态入口，点击打开系统文件夹选择器；有目录后显示目录列表，末尾为“添加文件夹”行。
- 添加第一个目录时，若名称为空，自动填入主目录的 basename；之后不再自动覆盖。名称为空或没有目录时禁用“创建项目”。
- 点击“创建项目”只打开 C28，不发送命令。C28 中确认后发送 `project.create`（带名称与 `trusted: true`）；取消、关闭或按 Esc 返回 C27，保留输入。服务端错误在创建弹窗中以本地化 alert 显示。
- 搜索浮层的“打开文件夹”与侧栏的“添加项目”走同一流程。主目录已存在时直接在已有 Project 中新建会话，未信任时沿用补确认流程。
- 不提供手动路径输入。`host.pickFolder` 返回 `unsupported` 时，在原位置显示 alert，“添加文件夹”保持可用。删除现有手动路径输入及其文案和 README 说明。
- C28 宽 416px，标题为“信任这些文件夹吗？”。正文是一个高度受限的 ScrollArea 列表，显示全部目录的完整路径（等宽字体，可换行），主目录带“主要”徽标；编辑场景中新增目录带“新增”标记。说明文案采用 pen 的通用表述，不再分别说明主目录与附加目录的影响。
- C28 的操作纵向排列、占满宽度：主操作 36px，依场景为“信任并创建”、“信任并保存”或“信任”（补确认和移动会话）；次操作“取消”32px。提交中两者都禁用；初始焦点仍放在取消。旧 Project 补确认与 Session Move 也复用这个多目录弹窗。

### 目录行（C27 与 C29 共用）

- 每行 32px：文件夹图标、目录 basename、行尾操作区。basename 与同一列表中其他行重复时，在名称后用 `text-ui-caption` 附加父目录名。
- 主目录行显示 24px 带描边的“主要”徽标。非主要目录行在 hover 或 focus-within 时，于移除按钮左侧显示 24px ghost“设为主要”；空间预先保留，显示时不改变行宽。
- 每行的 28px 移除按钮在只剩一个目录时禁用。移除主目录时，下一个目录成为主目录。
- hover 或 focus 时，在行上方 4px 显示完整路径提示，使用新的作用域 token `path-tooltip` / `path-tooltip-foreground`（深底浅字），`text-ui-sm`，8px 内距、8px 圆角，可换行。全局 `tooltip` 角色不变。
- 编辑弹窗中的“设为主要”只改变表单状态，保存时随 `project.update` 一起提交。

### 编辑项目（C29）与移除确认（C31）

- 编辑弹窗宽 520px，预填当前名称与全部目录，目录列表末尾为“添加文件夹”行。
- 底栏左侧是实心 destructive“移除本地项目”（32px）；右侧是 ghost“取消”（32px）与 primary“保存”（36px）。没有修改或名称为空时禁用保存。
- 保存时，若已信任的 Project 新增了目录，先打开 C28（主操作“信任并保存”），确认后发送带 `trusted: true` 的 `project.update`；取消则返回编辑表单，不保存。其他情况直接发送 `project.update`。冲突与保留目录错误在编辑弹窗中以 alert 显示。
- 欢迎页底部 Project 下拉中的“项目目录”改为“编辑项目”，打开 C29；原只读目录弹窗删除。
- “移除本地项目”打开 C31：宽 448px，标题“移除 {name}？”，说明“这只会从应用中移除该项目。你电脑上的文件和现有聊天不会被删除。”，ghost“取消”与 36px 柔和 destructive“移除项目”。柔和 destructive 使用新 token `destructive-soft` / `destructive-soft-foreground`，作为 DESIGN.md 中该确认框的作用域例外。
- 确认后发送 `project.remove`，关闭两个弹窗；取消、关闭或按 Esc 返回 C29。项目下有 Session 执行中或等待交互时，禁用“移除本地项目”并说明原因；服务端的 `session_busy` 作为兜底，以 alert 显示。
- 当前打开的会话属于被移除的 Project 时，该会话保持打开，标题栏和侧栏按“对话”呈现。

### 项目详情卡（C30）与项目行

- 侧栏项目行为 32px、8px 圆角：hover 时显示 `hover` 背景；当前会话属于该 Project 时显示 `selected` 背景。hover 或 focus-within 时，仅在行尾显示现有的“新建会话”按钮，空间预先保留。“⋯”图标与项目右键菜单本次不渲染。
- 详情卡宽 320px，12px 圆角，16px 内距，`popover` 表面加 overlay 阴影。依次为：项目图标、名称与图钉，会话数，分隔线，全部目录完整路径（家目录缩写为 `~`），分隔线，32px“编辑项目”行。
- 打开：指针在项目行停留约 300ms，或项目行获得键盘焦点。关闭：指针离开项目行和卡片约 150ms 后，或按 Esc。卡片以门户渲染：左边缘距项目行悬停背景矩形右边缘 4px，顶边对齐；可以覆盖中间导航，不受其滚动裁剪，并按应用视口夹取。4px 间隙保留指针通道。
- 图钉是临时固定：固定后指针离开不关闭，再次点击图钉、按 Esc 或点击外部才关闭；状态不持久化。“编辑项目”关闭卡片并打开 C29。
- 将来加入“⋯”菜单时，菜单与详情卡互斥：打开菜单会关闭详情卡。本次实现的打开状态需要能被外部关闭，以容纳这条规则。
- 卡片由已安装的 beUI Popover 受控组合，打开状态由项目行的 hover/focus 意图驱动，不新装 HoverCard。

### 弹窗外观

- C27、C28、C29、C31 统一：16px 圆角，内距上下 20px、左右 24px（窄屏 16px），分区间距 12px；32px 标题行用 `text-ui-lg` medium，右侧 32px 关闭按钮；输入框与普通按钮 32px，主要操作 36px，控件圆角 8px。
- 这些尺寸由项目弹窗传给已安装的 MorphingModal，不修改其全局默认值，其他使用者的几何不变。

### 文案与文档

- zh 与 en 同步新增或修改：项目名称、源文件夹、空状态提示、添加文件夹、主要、设为主要、新增、信任标题与说明、信任并创建、信任并保存、编辑项目、移除本地项目、移除确认标题与说明、移除项目、会话数、无法选择文件夹、`project_trust_required` 错误。删除手动路径、“项目目录”与主目录/附加目录分述等不再使用的键。
- DESIGN.md 的 Project directories and trust 段落按 pen 的 C27–C31 重写：统一信任确认、目录行与路径提示、编辑与移除确认、详情卡锚定（保留现有锚定规则），以及 `path-tooltip` 与 `destructive-soft` 两个作用域 token。三栏底色与阴影段落沿用当前分支中已有的修改。
- CONTEXT.md 的 Project 词条补充：名称可编辑；目录可增删；新增目录需要信任确认；移除 Project 只删除登记，会话回到“对话”。
- 更新 ADR-0041：名称可编辑、目录编辑、新增目录的信任提升、移除登记，以及编辑后打开状态的派生。
- 同步 ui 与 server README 中 Project 命令与文件夹选择器回退的说明。

## Testing Decisions

- 测试只验证公开行为，遵循 [docs/testing.md](../../docs/testing.md)。每项行为选择最高的现有接缝，不新增接缝。
- **服务端 wire**：沿用 server 测试中的真实 WS、SQLite 与隔离 dataRoot。覆盖以下行为：
  - `project.create` 的名称校验，以及复用已有主目录时保留原名称。
  - `project.update` 改名、增删目录、切换主目录。
  - 已信任项目新增目录时，缺少 `trusted` 返回 `project_trust_required`；未信任项目新增目录后保持未信任。
  - 移除目录后，相关会话的归属、附加目录与 `trustedProjects` 派生随之变化。
  - 冲突检查排除自身，保留目录被拒绝，空目录列表或不属于列表的主目录被拒绝。
  - `project.remove` 只删除登记，Session、置顶、归档保留；执行中或等待交互时返回 `session_busy`。
  - 已打开且空闲的 Session 在下一次空闲执行时按新配置重开。
  - 新命令进入同一变更队列。
- **UI app 层**：在 Chromium browser 模式下渲染 App，通过现有 fake wire helper 观察命令与渲染，并扩展该 helper 以支持 `project.update`、`project.remove` 与 `name`。覆盖以下行为：
  - 创建流程：名称自动填入且可修改，空名称或无目录时禁用。
  - 点击创建后统一信任；取消后保留输入且不发送命令。
  - 选择器返回 `unsupported` 时显示 alert。
  - 目录行的重名区分；hover 与键盘焦点下显示路径提示和“设为主要”，且不改变几何。
  - 编辑弹窗：改名、增删目录、主目录接任、最后一个目录不可移除；已信任项目新增目录时先确认；冲突以 alert 显示。
  - 移除确认的取消与确认，以及有忙碌会话时禁用。
  - 详情卡：hover 延迟打开与关闭、键盘焦点打开、指针穿过间隙、图钉固定、Esc 与外部点击关闭、编辑入口、会话数不含已归档。
  - 项目行的 hover、选中背景与“新建会话”。
- **时间**：详情卡的延迟测试使用 Vitest 虚拟时钟，分别在截止时间前与到达截止时间时断言，并在 `finally` 中恢复。transcript 与 model-services 的浏览器测试已有先例。
- **布局**：开始改动前，按 DESIGN.md 的 layout preservation gate 记录基线。layout 浏览器测试改为断言新的四个底色，并新增工作区阴影断言（Light/Dark 两层值，且只出现在工作区容器上）；栏宽、高度、圆角、留白断言保持不变。详情卡的锚定（4px 间隙、顶边对齐、视口夹取）用元素矩形断言。
- store 的 Node 测试覆盖新的 Project 字段解析（如有变化）。
- 交付前按 AGENTS.md 做一次 agent-browser GUI 验收：Light、Dark 与窄宽度截图，检查光标、hover、焦点、控制台与网络错误。外壳阴影与项目弹窗各在受影响页面检查一次。

## Out of Scope

- 项目“⋯”菜单与项目右键菜单，以及其中的置顶、分区、归档聊天、移除操作。
- 详情卡图钉状态的持久化。
- 手动输入路径。
- 全局 tooltip 的配色调整。
- 撤销 Project 信任、删除目录文件、把会话从项目中移出到“对话”的独立操作。
- 设置页内部表面的配色调整，以及 TUI 外观。
- 原生 Electron 窗口几何验收（需要单独的平台授权）。
