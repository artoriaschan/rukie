# TUI 全屏布局访谈

Status: design confirmed and implemented; validation limitations recorded

## 已确认的需求

- `neant` 全屏展示；退出后清除本次 TUI 展示的内容。
- 布局参考 dsh-TUI：主体滚动，输入框固定在底部。
- 使用 grill-with-docs 逐轮确认设计并记录决策；Q1–Q19 均已确认，用户最终回复“确认设计，开始实施”。

## 实施前核实的事实

Neant 的事实与源码行号基于实施起点 `a8fc5eb92e0d8d404a87cc7c20d687741c20b815`；实现后的行为与验收见实施记录。

- ADR-0005 与现有 TUI spec 采用 inline 模式：完成的内容写入终端 scrollback。全屏要求需要修订这一默认选择。
- 当前 Chat 把 Logo 和完成的消息交给 Static；活动回复、工具、工作状态行、审批与输入框排列在活动区中。
- 当前终端生命周期恢复 raw mode、光标和 bracketed paste，但未进入 alternate screen。
- 本机 dsh-TUI 的全屏 Chat 使用可滚动的消息区，以及不随主体滚动的底部输入区；消息区包含 Logo，支持跟随底部输出。
- `Transcript` 是持久化的消息记录；界面退出清理与删除 Transcript 是两个不同动作。
- dsh-TUI 全屏还实现了应用内文本选择与自动复制；这不是全屏布局本身的必然要求。终端原生选择的绕过手势取决于终端程序，不可假设所有终端都使用 Shift。
- dsh-TUI 的翻页步长是主体视口高度减 1 行，滚轮的默认步长是 3 行；暂停跟随时提供回到底部提示。
- dsh-TUI resize 保持底部跟随或手动行偏移，不保证宽度重排后的消息文本锚点。
- Neant 的 `Session.messages` 是恢复后的模型上下文，TUI resume 从该字段回放，隐藏 compaction summary；因此早于压缩的原始消息仍在存储中，但不在恢复后的消息区中。当前运行中的已展示条目不会因 compaction 被移除。

## 第一轮：已确认（2026-10-02）

用户回复：全部采用推荐。

- Q1：`neant` 只提供全屏体验，本次不增加 `--inline` 用户选项；Headless CLI 保持当前输出方式。
- Q2：退出恢复启动前的终端内容和光标；本次 TUI 不残留，也不清空原终端历史；Session 仍可恢复。
- Q3：滚轮与 PageUp/PageDown 滚动消息区，Ctrl+End 回到底部；普通方向键与 Home/End 用于输入编辑。
- Q4：底部自动跟随；上滚后暂停跟随，新输出不移动阅读位置；回到底部恢复跟随。
- Q5：输入区随换行增长，最多 6 行且不超过终端高度的三分之一（包含上下分隔线）；更长草稿内部滚动，保持编辑光标可见。
- Q6：审批在底部替换输入框；工作状态行与状态栏保留，消息区仍可滚动。
- Q7：Logo、model 与 cwd 启动信息置于消息区开头，随主体滚动；不增加固定顶部栏。

以上是已接受的设计方向，产品实现尚未开始。后续轮次仅确认其派生边界，不重新询问已经确认的选择。

## 第二轮：已确认（2026-10-02）

用户回复：全部采用推荐。

- Q8：本次保留终端原生选择与复制，不实现 dsh-TUI 的应用内拖选、自动复制；开启滚轮上报后使用当前终端提供的原生选择手势。
- Q9：暂停跟随时，底部专用一行显示“Ctrl+End 回到底部”；收到未读的新输出后改为“有新输出 · Ctrl+End 回到底部”。已有流式回复的增长也算新输出，不按 chunk 计数。
- Q10：窗口 resize 时，跟随状态继续贴底；浏览历史时保持当前首条可见消息及其阅读位置，宽度重排不直接跳到底部。
- Q11：常规尺寸自动调整消息区与输入区；小于 40 列或 12 行时显示调整窗口提示，暂停输入编辑和审批决定，保留中断/退出，不主动取消 Run 或丢弃草稿。
- Q12：审批区最多占终端高度的一半，参数可内部滚动且完整可读，选项与操作提示固定；Tab 切换消息区/审批详情滚动焦点，PageUp/PageDown 作用于当前焦点区，方向键继续选择审批决定。
- Q13：本次沿用现有的压缩后上下文回放策略，不新增完整 Transcript 展示接口；当前运行中的旧消息持续保留，完整历史回放另行处理。

第一、二轮共确认 Q1–Q13；其派生边界已在第三轮确认。

## 第三轮：已确认（2026-10-02）

用户回复：全部采用推荐。

- Q14 非交互终端：启动时检查 stdin/stdout 为 TTY 且 TERM 不是 dumb；不满足时，在进入 alternate screen、创建 Session 或请求模型之前退出，给出使用 neant-cli 的说明，不退回 inline。
- Q15 主动提交：用户提交新消息时回到底部、恢复跟随并清除新输出提示；单纯编辑草稿不改变消息区阅读位置。
- Q16 审批滚动焦点：审批打开时滚动焦点默认消息区，Tab 在消息区与审批详情之间切换；滚轮作用于指针所在区域，Ctrl+End 始终让消息区回到底部。审批结束后恢复输入草稿与正常编辑焦点，不自动提交草稿。
- Q17 长会话：当前运行中已展示的消息全部保留，不为控制内存静默删除旧条目；仅绘制视口并复用布局结果。保留现有 Session/Transcript 语义，不以完整历史接口扩展本次范围。
- Q18 退出和异常：保留现有按键语义（Run 中 Esc/Ctrl+C 中断，审批中 Esc 拒绝、Ctrl+C 中断；空闲 Ctrl+C 先清草稿、连续两次退出；空草稿且空闲时 Ctrl+D 退出）。正常退出、可处理的异常和 SIGINT/SIGTERM 都先恢复终端模式与原画面；致命错误随后写入 stderr，不回灌整段对话。
- Q19 验收范围：覆盖 80×24、40×12 与阈值以下窗口；长消息、流式增长、暂停/恢复跟随、resize 阅读锚点、多行草稿、审批滚动与焦点、compaction 和 resume；以终端公开接口测试退出前后原画面恢复及可处理异常清理，并进行真实终端滚轮、复制与退出验收。同步修订 TUI spec 和 ADR，保留 Headless CLI 回归。

## 最终共享理解（已确认）

用户回复（2026-10-02）：确认设计，开始实施。

`neant` 使用 alternate screen 全屏展示。退出恢复启动前的终端画面、光标及终端模式，本次 TUI 内容不残留，Session 仍持久化且可恢复。仅交互式终端允许启动；Headless CLI 保持原有行为。

界面只有滚动主体和固定底部区：Logo 与启动信息随消息滚动；已完成消息、当前回复和工具均在主体。底部保留工作状态、输入或审批、状态栏与暂停跟随提示。输入最多 6 行且不超过终端高度三分之一（包含上下分隔线）；审批最多半屏，参数可滚动、选项固定。小于 40 列或 12 行时暂停编辑和审批决定，保留中断/退出与草稿。

主体支持滚轮和翻页；浏览历史暂停跟随，新输出只更新提示。回到底部或提交新消息恢复跟随。resize 保持底部跟随或当前阅读消息及位置。Ctrl+End 始终回到主体底部，审批时 Tab 切换滚动焦点；文本选择与复制沿用终端原生能力。

保留当前运行中所有已展示消息，沿用现有 resume 的压缩后上下文投影。本次不增加完整 Transcript 回放、用户可选 inline 模式或应用内拖选/自动复制。渲染管线及 dsh-TUI 代码复用边界沿用 ADR-0005。

实施需覆盖 Q19 的终端公开接口回归和真实终端验收，修订 TUI spec，并确保 Headless CLI 回归通过。实施进度与实际验收结果见 [实施记录](implementation.md)。
