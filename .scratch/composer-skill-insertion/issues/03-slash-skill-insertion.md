# 03：用 `/` 插入技能（主线示踪）

Status: ready-for-agent
Blocked by: 01

**What to build:** 按 [spec](../spec.md) 的「插入列表」「技能标记」「技能数据」各节，打通第一条完整路径：用户在输入框开头输入 `/`，在输入框上方看到技能列表，选中后输入框开头出现蓝色技能标记，发送后 Agent Core 识别为 Skill Invocation。本票的列表只包含「技能」一组，内置命令由 05 加入。

- [ ] Agent Core 技能列表返回 `scope`（user/project）与 `filePath`，同名时项目覆盖用户，只返回生效项
- [ ] wire 新增不依赖 Session 的技能列表命令，参数为项目或会话标识，无项目时只返回用户级技能；server 校验与测试
- [ ] DESIGN.md 先补技能标记与插入列表规范（颜色、间距、行高、图标、截断与收缩规则），全部使用已有角色
- [ ] 列表在输入框上方、与输入框同宽；最多 10 个可选项，超出滚动并保持高亮可见；组标题「技能」，空组隐藏
- [ ] 技能行：图标、名称、名称后的描述、右侧「全局」或「项目」标签；单行，描述截断并悬停显示全文；窄宽度先收描述、再截名称，右侧最后截断；按名称字母排序
- [ ] 仅当输入以 `/` 开头、光标在首行且 `/` 后无空白时出现；按名称过滤，不区分大小写，前缀优先；无匹配时关闭，回车发送原文
- [ ] 焦点留在输入框；上下键、回车、Tab、Esc、点击；组合框与选项的无障碍语义
- [ ] 技能标记为 token 模式 TextNode：整体删除、光标不可进入、只能是第一个节点、再选替换；选中替换 `/xxx`，光标在标记后并补一个空格
- [ ] 发送序列化为 `/名称 正文`，只有标记时为 `/名称`；Run 进行中作为插话提交
- [ ] 每次打开列表先显示缓存再后台刷新；新会话页按选中项目取数，切换项目时刷新
- [ ] 浏览器测试覆盖上述交互、窄宽度与无障碍语义，并验证发送内容被 Core 识别为技能调用
