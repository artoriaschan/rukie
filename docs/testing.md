# 测试策略与可靠性约束

新增、修改或审计测试时必须遵守本文。执行命令和验收顺序见[根规则](../AGENTS.md#tests-and-verification)；本文拥有测试层级、隔离、同步和审查约束。策略参考 DeepSeek Harness 的分层测试与 CI 可靠性规则，按 Rukie 的 Bun、Session 与终端运行方式适配。

## 选择验证层级

| 行为                                | 主要证据                                                | 集成证据                                     |
| ----------------------------------- | ------------------------------------------------------- | -------------------------------------------- |
| 解析、格式化、状态转换、保留上限    | 所属模块的输入和输出；固定数字与确定性数据              | 小型代表性场景验证接线                       |
| Session、权限、工具、恢复与后台任务 | `createSession`、脚本化模型与真实执行、存储             | 重读文件或恢复 Session，检查副作用与提交结果 |
| TUI 输入、面板和滚动                | app `start` 与 headless terminal 的行、单元格和交互结果 | 代表性组合场景覆盖共存、resize 与输入归属    |
| 超时、提示期限、动画和点击时间窗口  | 注入或虚拟时钟，验证截止前和截止时                      | 只保留虚拟时钟无法覆盖的真实进程或传输合同   |
| 打包、安装和发布恢复                | 保存的真实包、隔离本地注册表、实际安装入口              | 退出状态、安装后的文件和注册表状态           |

只替换模型、外部网络或时间等昂贵或不可控边界；工具、权限、持久化和 Frontend 的下游路径保持真实。模型说“写入成功”不能证明文件已写入，退出提示不能证明子进程已退出。功能正确性不以执行耗时、覆盖率或绿色重试次数代替。当前仓库没有录制会话与真实提供方测试车道，不把其他项目的快照命令或覆盖率阈值当作已实现门禁。

## 同步与竞态

- 面板或滚动隐藏运行指示不代表 Run 已结束；提交下一条问题前必须观察聊天的 idle footer 或实际完成信号。
- 输入框、raw mode 和空闲只证明相应的输入前提；恢复、工具输出与页脚断言必须等待各自的已呈现结果，不能用通用就绪状态替代。
- 非时间功能等待完成 Promise、事件、已提交状态、文件、进程退出或终端结果；禁止固定延时作为 readiness、完成或清理证据。
- 模型回复和 barrier 控制操作的先后与重叠。除非顺序本身属于产品行为，不断言并发回调的到达顺序。
- 明确完成边界：父 Run idle 不代表 Background Job、Subagent、通知和关联 Request 已结算。删除 fixture 前等待其拥有的工作结束。需要保持当前视口的组合场景，在后台通知实际提交后再完成脚本化父回复；否则独立 Reporter 新增输入可能改变阅读视口。专门测试 idle 通知时，显式驱动并等待 Reporter 结算。
- 时间是被测功能时才操作时钟。异步 I/O 期间推进显示时钟不能证明截止期限；待目标计时器注册后，明确验证截止前和截止时。父进程虚拟时钟不能推进子进程计时器。
- 等待上限只用于终止失败并给出诊断。删除功能测试中的“必须在 1 秒内完成”等机器速度断言；性能预算放在明确的性能测试中，说明运行环境和样本，不能混入普通功能 gate。
- 对真实传输延迟的模拟必须在调用旁说明 `test-policy: transport-delay` 及理由。该例外只用于模拟被测传输，不允许等待它来代替同步信号。

## 隔离与清理

Bun 的文件 worker、CI 的四个 shard 和独立测试进程可能并行。进程隔离不隔离宿主端口、文件路径、环境变量、进程组和外部服务。

1. 每次测试用 `mkdtemp` 分配项目与 home；端口由服务直接绑定 loopback 的 `0`，禁止用先探测空闲端口再绑定来代替直接绑定。被测合同明确要求非零 callback port 时，可保留这种配置测试，但必须记录重新绑定的争用窗口与实际端口错误，不得 retry；一般网络 fixture 仍须直接绑定 0。解析输入中的固定路径和 URL 不属于资源分配。
2. 资源获得后立即登记释放。清理停止新工作、取消已有工作、移除监听并等待 exit、close 或 termination；只调用 abort、kill 或 close 不等于完成。应用 fixture 用 Bun `onTestFinished` 登记可重复调用的同一个清理 Promise，让 runner 在超时后等待收尾；测试体的 `finally` 可能仍悬在旧的异步等待中，不能作为唯一释放入口。虚拟时钟在拥有的应用关闭后恢复，迟到的 `finally` 不得恢复下一例的时钟。故意制造框架超时的回归在 hook 中完成准备，再对已悬置的测试体触发失败界限；不能让这个界限同时约束应用启动速度。初始化在 owner 超时后恢复时，同样停止新工作和迟到错误。
3. 优先注入实例配置。修改 env、全局时钟、mock 或注册表时记录原值是否存在，在最小 `try/finally` 范围恢复；可能在进入该范围前失败的初始化必须有清理 fallback。缺失的 env 恢复为缺失，不能赋值 `undefined`。
4. 全局状态测试不能标为 concurrent；不能为了修复一个未隔离 fixture 将整套测试串行化。
5. 平台拥有的时间精度、权限、信号和路径应以重新读取的事实断言。无法跨平台验证的合同明确标记平台与理由，不能降低所有平台的断言。
6. fixture 放在普通 helper 文件；禁止导入其他 spec，以免重复注册测试和昂贵副作用。

## 覆盖成本与失败处理

大数量、边界与保留上限由所属模块验证，端到端只保留足以覆盖接线的代表性数据。参数化必须覆盖不同规则或状态，不能仅重复等价 setup。组合场景保留确实需要同时发生的行为；独立的格式、鼠标坐标与持久化边界分开验证。

修改超过一秒的用例时检查真实等待、渲染次数、进程启动和清理。保留真实集成成本时记录原因与 focused timing；扩大超时不是提速。重跑只补充稳定性证据，不能代替 barrier 控制的竞态复现。禁止用 retry、吞错、放宽结果断言或正规化不稳定输出掩盖缺陷。

概率性失败先保存失败提交、命令、worker/shard、日志与实际结果，再用最小集合判断资源冲突、状态泄漏、错误同步、清理未完成或真实产品缺陷。单独通过而组合失败是待解释的测试或代码缺陷；不得直接归因于 runner。不对同一状态反复运行完整套件求绿。

## 门禁与审查证据

`bun run check:test-policy` 纳入 `check:dev`，扫描 `packages/` 和 `scripts/` 的测试及 fixture 的 TypeScript AST，拒绝直接固定延时、timer Promise 的直接成功 resolver、`test.only`/`describe.only`/`it.only` 和跨 spec 导入。字符串中的示例不属于可执行调用。门禁有拒绝样本回归测试，允许带理由的传输延迟及作为失败上限的拒绝计时器。

静态门禁只检测上述语法，不能证明间接 helper、shell 脚本、资源清理或断言的意义。审查仍须逐项确认：真实入口、外部结果、完成信号、资源 owner、故障清理、全局恢复、平台条件、distinct cases 和时间断言的必要性。审计记录必须区分全量扫描与人工核查，列出范围、发现、修改、保留理由和未验证环境；不能把扫描通过描述为所有用例都稳定。

本地最终验证与需要完整运行的条件遵循[根规则](../AGENTS.md#tests-and-verification)。普通 PR 在受影响测试和静态检查通过后交接，CI 负责最终全量验收；交付证据区分本地通过、CI 待验收与最新提交 CI 已通过。检查失败时查看完整日志，pending、失败、取消、跳过或已被替代的运行不算验收成功。

## 桌面测试入口

`packages/ui` 和 `packages/desktop` 用 Vitest，由 Node 执行。ui 的 React DOM 测试使用 Playwright Chromium browser mode，纯 store/client 测试使用 Node；desktop main/preload 使用 Node 环境。ui 的浏览器测试命名为 `*.browser.test.ts(x)`，Node 测试为其他 `*.test.ts`，各自的 include/exclude 由包内 `vitest.config.ts` 定义。Bun 包继续使用 `bun:test`；`check:test-policy` 拒绝跨 runner 导入，根 `bunfig.toml` 排除 ui/desktop，普通、parallel 和 shard 收集都遵循该边界。

本地先执行 `bunx --no -- playwright install --only-shell chromium`，再执行 `bun run test:desktop`；浏览器不在 postinstall 自动下载。PATH 上需要支持 Vitest 的 Node，禁止 `--bun`。缺失浏览器会令测试失败，安装后再运行。`test:desktop` 接入本地 `check`，不接入 `check:dev` 或 GitHub Actions；涉及 ui/desktop 的 PR 交付证据必须附本地结果。Chromium browser mode 验证浏览器 DOM 行为，不能替代打包后 Electron 的冒烟验证。
