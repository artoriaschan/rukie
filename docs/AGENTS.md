# 文档编写规范

本文件规定 Rukie 文档的归属、结构、表达与验证方式，适用于 `docs/` 及其引用的项目文档。仓库通用工程规则见[根 AGENTS.md](../AGENTS.md)。

## 文档归属

每类事实只有一个权威位置。其他文档说明该事实与当前主题的关系，并链接到归属位置；代码、配置与脚本已能直接回答的问题，优先指向它们。

## 结构与范围

维护操作遵循[文档流程](agents/documentation.md)，使用 [rukie-doc](../.agents/skills/rukie-doc/SKILL.md) 选择包 README、参考、教程或决策模板。ADR 状态与格式由[决策记录规则](adr/README.md)定义。

参考文档按职责或查找主题组织，说明当前行为。教程按到达结果所需的步骤组织，先交代前提，再给操作与可观察的验证结果。较长教程和参考分开；短例子可以留在参考内，并标明适用条件。

高层文档说明直接下层的目的、责任和协作关系。需要字段、调用参数或局部生命周期细节时，链接到拥有它的 README、专项文档或源码；架构文档不展开完整 API 清单。

## 表达规则

- **描述当前行为。** 用现在时说明已存在的机制。需求与计划放入 `.scratch/`，架构决定放入 ADR；运行参考中不混入实施进度或设想。遇到决定与代码不一致，明确记录差异并解决，不把计划写成事实。
- **术语统一。** 使用 `CONTEXT.md` 中的 Agent Core、Frontend、Session、Run、Turn、Transcript 等词。同一概念在正文、图表和例子中保持相同名称。
- **说明完整义务。** API 与配置说明覆盖适用条件、输入来源、可观察结果、失败、取消、持久化和资源归属中与该主题有关的部分。注释与 JSDoc 留在声明处，说明调用方实际需要知道的行为。
- **直接陈述。** 写清谁执行什么、何时执行、影响什么；用具体模块、API、事件和字段名。删除推理过程、修改经过、逐行代码复述和重复的测试讲解。
- **保留事实的唯一归属。** 调整实现时，同步更新拥有该行为的文档和例子；其他位置更新链接或概述，不复制整段定义。
- **每段一个物理行。** 依赖编辑器软换行；列表、表格和代码块保留结构。每段围绕一个主题，多个独立规则拆成列表。
- **语言与本地化。** 沿用现有文件语言；新的人类参考文档默认中文，代码标识与领域术语保留原名。仓库未建立中英文配对流程，不自动生成双语副本；用户要求配对时，两个版本一起核对。
- **强调有节制。** 标题用于导航，加粗用于区分并列规则；避免满段加粗、全大写与情绪性措辞。

## 示例、图表与引用

示例使用仓库现有 API 和脚本，注明必要配置、运行目录和外部服务条件。可运行的 TypeScript 示例必须在当前依赖与运行时下验证；省略部分代码时说明省略内容，示意结构使用 `text`，不伪装成可执行示例。凭据使用明确占位符。

图表只展示当前主题需要的关系。依赖图用箭头表示调用或依赖方向，并在正文说明；生命周期图使用 Rukie 的 Run/Turn 定义。图表与正文一起更新，不用颜色或标签宣称实施状态。

当前仓库文件使用相对 Markdown 链接；外部资料使用可访问的原始来源。历史证据留在 ADR 或调查记录，并标明对应版本或提交。不要将本机绝对路径、另一仓库专用脚本或缺失的插件技能写成项目通用要求。

## 篇幅与验证

篇幅以职责为准：先把下层细节移到拥有它的位置，再精简重复表达；完整的使用条件与失败说明不能为了压缩篇幅而删除。根规则保持简短，架构保留运行主线，专项文档承载局部细节。

`bun run check:docs` 校验维护文档的本地链接、ADR 格式和仓库 skill 元数据，并纳入 `check:dev`。[维护流程](agents/documentation.md#验证命令)说明检查范围与人工核对项。文档预算和示例编译仍由审阅与实际操作验证落实。

文档交付前逐项核对：

1. 对照当前源码、配置与 ADR 确认行为、所有者、术语和示例；检查当前范围内的每个相对链接及锚点。
2. 检查重复内容、混入的计划、过时版本、未验证的命令，以及正文和图表之间的矛盾。
3. 从根目录运行 `bun run docs:update` 同步 ADR 索引，再运行 `bun run check:docs`，对修改的 Markdown 运行 `bunx --no -- oxfmt --check <files>`，并运行 `git diff --check`；RTK 环境按根说明加前缀。
4. 代码一起变化时按根说明运行相关行为测试与完整检查；仅文档变化时报告文档检查结果，不把它描述为代码测试通过。

更新本规范时编辑真实文件。根 `CLAUDE.md` 仍指向根 `AGENTS.md`，不要用文档编辑覆盖该软链接。
