# 开发版共用配置与凭证，Session 按工作区隔离

## 问题

开发桌面应用切换 checkout 后，原有供应商不可见。用户确认开发版应共用供应商、凭证和设置，而会话继续按工作区隔离。

## 决定

本决定部分替代 [ADR-0035](0035-desktop-isolated-sqlite-storage.md) 中开发数据全部归 checkout 的规则。正式应用、终端与开发应用之间的隔离及开发系统凭证身份不变。

开发入口确定公共配置根 `~/Library/Application Support/Rukie Development/configuration`，通过 Electron main 私有启动通道传给 sidecar。公共 `app.sqlite` 保存供应商、模型定义、凭证密文、用户设置、偏好和模型能力缓存。供应商与凭证仍在同一事务提交；偏好以事务内读取并合并补丁，保留其他工作区修改。读取配置与模型列表时读取数据库当前事实，其他已打开窗口不会自动收到跨进程通知。

每个 checkout 的 `.desktop-dev/data` 继续保存项目、置顶、Session 索引、Session SQLite、附件与文件历史。用户维护的 rules、skills、agents 文件仍归此数据根，本决定共享数据库设置，不增加文件同步。工具与权限的 home 保持真实 OS home。未指定公共配置根的正式应用和测试保持原来的单根存储。

入口拒绝公共配置目录和业务数据树的符号链接；不扫描旧工作区、不自动迁移或回退。恢复已知旧供应商属于用户显式请求下的一次数据操作；保留原数据，凭证只复制已有密文，不解密、不写入仓库。

## 备选方案

- 每个 checkout 独立配置：安全边界简单，但不能满足用户复用配置的要求。
- 所有开发数据共用：省去重复设置，但会混合会话历史与项目状态；用户选择继续隔离会话。

## 影响

切换开发工作区保留供应商与设置。多个 sidecar 会打开同一个 WAL 配置数据库，需要验证事务合并、重启持久化与配置/Session 的分离。系统钥匙串授权仍由原生凭证操作决定；密文存在不代表实际请求已授权或网络调用成功。运行与验证证据归 [交付记录](../../.scratch/pencil-conversation-sync/spec.md)。
