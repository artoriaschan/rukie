# 桌面与 Web 主输入框使用 Lexical 纯文本编辑器

## 问题

主输入框是受控 textarea，只能保存纯文本。插入技能需要在输入框内显示带图标、整体删除、复制为 Markdown 链接的技能标记；textarea 无法给局部文字着色或嵌入图标，叠加高亮层的做法需要手工对齐文字、让出图标宽度并接管复制粘贴。

## 决定

桌面与 Web 的主输入框使用 Lexical 的纯文本编辑器，依赖按精确版本锁定并记入 [tech-stack](../tech-stack.md)。技能标记是 TextNode 的 token 模式自定义节点，节点文字为技能名，图标由样式表绘制；输入框对外仍以纯文本草稿和图片作为发送输入，由序列化函数把技能标记转为 `/名称 正文`，复制与粘贴格式由自定义剪贴板处理。回车发送、输入法合成、图片粘贴、焦点交接和输入框几何保持原行为。TUI 输入不受影响。

依据：[主输入框插入技能与 MCP Host](../../.scratch/composer-skill-insertion/spec.md)。

## 备选方案

- textarea 加透明高亮层（程小帮的做法）：实现轻，但标记没有图标、没有原子光标行为，复制粘贴无语义。
- textarea 前放一个前缀元素：依赖「最多一个标记且在开头」的限制，以后支持行内引用需要重做。
- ProseMirror 或 TipTap：能力相当，体量与扩展面更大；Lexical 官方覆盖紧凑聊天输入与 token 节点用例。
- 直接使用 contenteditable：需要自行处理输入法、撤销、选区与粘贴。

## 影响

输入框引入一个长期编辑器依赖，输入、焦点和布局回归测试需要覆盖 Lexical 行为。以后支持文件引用或多个行内标记时可以沿用同一节点模型。实施状态见[对应规格](../../.scratch/composer-skill-insertion/spec.md)。
