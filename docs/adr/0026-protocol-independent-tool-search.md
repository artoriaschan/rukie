# Tool Search 独立于原生追加能力，按模型 compat 选择工具声明格式

## 问题

[ADR-0025](0025-client-side-tool-search.md) 要求模型声明原生工具追加能力才启用 Tool Search，导致具备普通工具调用能力的自定义模型即使设置 `on` 也无法延迟 MCP 定义。同一协议的不同模型或网关可能支持不同的原生追加格式，不能仅从协议名称推断能力。

## 决定

Tool Search 的启用只取决于 `auto/on/off`、候选工具、上下文容量阈值和当前工具目录是否允许 `ToolSearch`，不以原生追加能力作为门槛。默认仍为 `auto`；保留候选定义估算 token 严格超过上下文窗口 10% 的阈值。

搜索发现继续经原生 `ToolControl.addTools` 提交到 Transcript。pi-ai 根据模型 compat 选择传输方式：支持原生追加时使用对应格式；未声明或关闭原生追加时，在下一次请求的普通 `tools` 列表中提供当前已加载定义。不根据协议名称强行开启能力标记，不新建模型循环、发现集缓存或协议适配层。

本决定部分替代 ADR-0025 的原生能力门槛和顶层工具列表始终固定的要求；保留其客户端检索、发现事实归 Transcript、声明顺序及 MCP 候选范围。Resume、Compaction、Rewind 和子 Session 继续使用当前分支的原生投影。设置和协议能力的使用说明归 [MCP Tool Search](../mcp.md#tool-search)。

未声明原生能力的选择规则由 [ADR-0027](0027-native-tool-capability-probing.md) 部分替代：Responses 和 Messages 在需要追加时通过独立请求探测，失败则使用普通声明；本记录的启用条件与工具发现事实归属继续有效。

## 备选方案

- 按协议默认打开原生追加能力：配置简单，但会向仅部分兼容的模型或网关发送无法接受或被忽略的格式。
- 保留原生能力门槛：有利于保持缓存前缀，但排除了普通工具调用模型的按需加载。
- 另存已加载名称并自行重建请求：可以实现通用加载，但重复 Transcript 和 pi-ai 已有职责，增加恢复及 Rewind 分歧。

## 影响

用户无需为通用 Tool Search 配置原生能力标记或切换协议。普通声明路径在发现工具后改变顶层工具列表，可能降低前缀缓存命中；原生能力仍可作为优化显式声明。一次搜索往返、工具执行权限和默认容量阈值不变。

验证须覆盖各支持 API 的真实请求序列：首轮不包含候选定义，发现后按所选格式提供定义，恢复后保留可见状态；原生追加路径继续保持初始工具列表。当前支持 API 与 compat 字段归配置 schema，避免由协议名称推断所有模型的能力。
