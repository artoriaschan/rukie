# 原生工具追加能力通过独立请求探测，失败时使用普通工具声明

## 问题

同一 `openai-responses` 或 `anthropic-messages` 协议的模型和网关不一定支持原生工具追加。要求用户逐个标注 compat 增加配置成本，直接按协议开启则可能导致请求失败。探测请求也不属于用户任务，不能污染 Transcript、恢复输入和任务用量。

## 决定

模型配置模块包装 pi-ai Provider，复用其认证、流接口与协议适配器。只有请求包含后续工具追加、协议属于 Responses 或 Messages、且所需能力未被显式确定时，才执行独立探测。探测构造一次合成工具追加并强制调用新增的无副作用工具；只有收到该工具调用才确认支持，不执行探测工具。显式 compat 优先于推断值；明确关闭能力或完整开启能力时跳过探测。其他协议保持普通工具声明。

探测不经过 Session 或 Harness，不调用任务请求的遥测回调，不写入 Transcript。诊断与探测用量独立保存在用户目录的能力缓存中；缓存按 endpoint、API、provider、model、凭据与 headers 的指纹隔离，不保存 endpoint、凭据或响应原文。成功结果有效 24 小时，明确不支持有效 1 小时，未知结果有效 60 秒。取消不缓存有效结论；请求受调用方取消及 10 秒超时约束，同进程并发共享探测。缓存读写失败不阻塞任务。

只有 HTTP 400/422 明确拒绝原生工具追加或对话内 system 格式才记为不支持。网络、认证、限流、服务端错误和未调用探测工具均为未知，当前请求使用普通 `tools` 声明；过期后可重新检测。真实任务的原生请求若在输出内容前明确拒绝该格式，缓存不支持并使用普通声明重试一次；已输出内容、其他错误或取消不得因能力检测重放。

本决定部分替代 [ADR-0026](0026-protocol-independent-tool-search.md) 中“未声明能力始终使用普通声明”的选择规则，保留 Tool Search 启用条件和 Transcript 的工具发现事实。推断仅作用于请求的模型副本，不改写用户设置或模型注册表；所有协议投影仍由 pi-ai 执行。

## 备选方案

- 按协议默认开启：忽略部分兼容网关和模型差异，会向服务发送无法处理的格式。
- 只要求用户手动配置：行为明确，但用户需了解服务端细节；保留为覆盖自动检测的入口。
- 在真实对话插入探测消息：减少独立调用，但污染任务历史、恢复与用量；不采用。

## 影响

首次工具追加可能增加一次模型调用和最多 10 秒等待，探测会产生服务端费用。能力判断由 endpoint 的当前响应决定，缓存减少重复开销，TTL 允许服务更新后重试。普通声明回退可能降低前缀缓存命中。探测用量不会混入 Session 用量，单独诊断便于排查。

验证覆盖两种协议的真实 SDK 请求、原生与普通声明、明确拒绝和未知错误、取消、并发缓存、过期、凭据隔离、显式覆盖及恢复后 Transcript 不含探测消息。缓存只优化请求格式，不参与 Session 的发现事实或工具执行权限。
