# WebFetch 在执行层限制公网请求，跨源跳转重新授权

## 问题

用 bash curl 读取网页缺少域名授权、内容转换与内网访问边界。域名获准也不能保证重定向或再次 DNS 解析仍指向同一允许目标。

## 决定

web_fetch 提供不携带本地凭据的公开 HTTP(S) GET。域名规则与 hooks 管理授权；执行层仍校验最终 URL、协议、地址及资源限制，hook 改写和 full-access 都不能绕过。结果声明为不可信外部内容，HTML 转为 Markdown；本轮不增加搜索、登录、非 GET 或模型提炼能力。

直连时校验全部 DNS 地址，任一非公网地址导致拒绝，再将连接钉在已校验地址上并按 hostname 校验 TLS。同源重定向每跳重做校验；跨源不自动请求目标，返回新 URL，让模型重新调用并重新授权。

采用 HTTP(S)_PROXY / NO_PROXY 环境代理时，域名解析与实际目标连接由代理负责，Core 不宣称提供直连相同的 DNS 钉定保证；IP 字面量仍受地址分类约束。产品设置不提供放开私网的开关。请求有总超时、下载与输出预算，并随 Run 取消。

依据：[WebFetch 规格](../../.scratch/web-fetch/spec.md)。Bun 下的 undici 导入与 dispatcher 限制保留在实现注释，精确依赖归 [tech-stack](../tech-stack.md)，不在本记录复制版本表。

## 备选方案

- 继续让模型用 bash curl：权限粒度与网页内容处理留给每次调用，无法建立专用执行边界。
- 自动跟随跨源重定向：原域名授权被扩展到用户未批准的新源。
- 允许配置关闭私网限制：规格明确排除；代理解析则作为单独、明确的信任边界。

## 影响

允许域名不等于允许任意重定向目标。代理环境的网络限制依赖代理自身；Fake-IP 环境可能需要使用代理分支。安全测试使用可控 DNS 与本地服务器，公开网站和代理的实时可用性需另行验证。
