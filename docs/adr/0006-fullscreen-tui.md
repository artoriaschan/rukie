# TUI 使用全屏消息区与底部输入区

Status: accepted

`neant` 采用 alternate screen 全屏展示：消息区可滚动，输入或审批区固定底部；退出恢复启动前的终端画面、光标和模式，Session 的持久化不受界面清理影响。仅交互式终端启动，本次不提供 `--inline` 选项，Headless CLI 保持当前行为。

这替代 ADR-0005 中 TUI 默认 inline 的选择。inline 把完成的消息交给终端 scrollback，退出后保留界面内容，无法满足独立滚动主体与固定输入区的要求。全屏模式需要由 TUI 管理消息浏览、底部跟随和阅读锚点，所有当前已展示条目仍保留；文本选择与复制采用下文的会话选字决定。自研渲染管线和 dsh-TUI 参考代码的复用边界仍沿用 ADR-0005。

用户浏览历史时暂停跟随，新输出只更新提示；回到底部或主动提交后恢复跟随，resize 保持阅读位置。输入区含分隔线最多 6 行且不超过终端高度三分之一，审批最多半屏并支持详情滚动；小于 40 列或 12 行时暂停编辑和审批，保留中断与退出。本次沿用现有 resume 的压缩后上下文投影。Q1–Q19 的完整确认记录、按键规则和验收范围见 [全屏 TUI 访谈](../../.scratch/fullscreen-tui/interview.md)；用户已确认最终共享理解并授权实施；验证结果见 [实施记录](../../.scratch/fullscreen-tui/implementation.md)。

## 会话选字与复制

2026-10-07，用户确认将会话选字与复制改为 dsh-TUI 的全屏交互，替代原先沿用终端原生选字的决定。参考版本为 `3c89ea516e4f7d2777efe979200016528722a0b4`。此决定已接受，渲染器与 TUI 的实现尚待完成；设计范围见 [流式消息访谈](../../.scratch/streaming-message-parity/interview.md)。

TUI 自行处理拖动、双击、三击和键盘延长选区，选择完成后自动复制并清除高亮。复制时核对选中的内容；流式更新替换了选中内容时拒绝复制并提示，避免复制出用户没有选中的文本。选择与复制沿用参考的平台及远程终端处理；终端恢复、阅读锚点和小终端规则继续保留。

终端原生选字无需由渲染器维护选区，但无法完整对齐消息交互与流式内容校验。此次选择自有选区，接受渲染器及剪贴板适配的维护成本，以使消息选择、流式变化和复制结果一致。

## 输入历史

输入历史参考 dsh-TUI：↑/↓ 先在输入内容的显示行间移动光标，到第一行/最后一行的边界后浏览历史；↑ 从最近一次输入开始，↓ 越过最新历史恢复浏览前的草稿和光标。历史回填到文本末尾，可继续编辑后提交。Ctrl+C 清空草稿或成功提交时结束本次历史浏览。

TUI 为每个规范化的工作目录保留最近 200 条已接受输入（包括启动时的位置参数），连续重复输入只留一条，空白和运行中拒绝的提交不记录。历史独立于 Session 和模型上下文，存于 `~/.neant/input-history/<工作目录 SHA-256>.jsonl`，重启即可回填。文件权限为 0600，新建历史目录为 0700；保存采用项目锁和原子替换，退出等待待写入历史完成。损坏记录跳过，读写失败仍保留当前进程的历史浏览能力。
